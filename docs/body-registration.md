# Real Participant Body Registration

This slice implements the user's requested path: Quest passthrough image → MediaPipe shoulder/hip landmarks → calibrated image rays → generic virtual organs on a reclining participant. It is **operator-assisted planar registration**, not automatic reconstruction of skin, joints, internal organs or table semantics. Physical alignment and reclining-person accuracy remain unverified until the wearer test below passes.

## Implemented Route

`NativePresentation` defaults to AR with Unity Meta OpenXR 2.3.0 `ARCameraManager`, `ARSession` and composition layers. Meta camera-pose plugin requires Linear color space; the built-in renderer is retained. The camera clears transparent; the virtual room and mannequin are hidden. The existing floor/head/controller rig remains the source of Unity world coordinates. Right stick click changes AR/full-VR during selection/recap and starts a fresh attempt. Full VR restores authored anatomy/port transforms.

`NativeBodyRegistration` starts with camera acquisition disabled, including when Android permission was previously granted. Left stick click is the operator's explicit opt-in after the participant agrees. It requests `horizonos.permission.HEADSET_CAMERA` and enables the official Meta MRUK 85 `PassthroughCameraAccess` left camera, requesting 640×480. Unsupported resolution may be negotiated by the SDK; returned dimensions are used throughout. Switching to VR, disabling the component or suspending the app stops acquisition. No participant recording/upload/export begins.

The operator sets three spaced points with the tracked right controller, clicking the left stick at each: near one shoulder, the other shoulder, and a hip, **just above the anterior torso/clothing surface**. The controller origin is the point; it is not a calibrated instrument tip. Do not use the tabletop below the body as the torso surface. The plane must be nondegenerate, approximately horizontal and face the observer. A fourth calibration click begins a replacement plane and invalidates the old fit.

At each observation, PCA supplies intrinsics/crop-aware rays, lens extrinsics and capture-time pose. The adapter caches these rays before HTTP inference, transforms the SDK tracking-space pose through the same `NativeWorkbench.trackingOrigin` as the head/controllers, and checks that OVR/OpenXR head spaces agree. It rejects absent/incompatible/stale camera timestamps, invalid lens rotations, and the SDK’s identity historical-head fallback using the required floor-space observer height (>0.25 m). Asynchronous GPU readback avoids Meta's documented preceding-frame behavior for blocking `Graphics.Blit`; JPEG conversion follows. No head pose sampled at response time replaces acquisition-time metadata. Image orientation still requires physical verification. [Meta PCA API](https://developers.meta.com/vr/reference/mruk/v85/class_meta_x_r_passthrough_camera_access/)

Raw JPEG travels over USB-reversed localhost port **8790** to `services/registration`. `POST /pose` echoes the exact `X-Frame-Id`, image dimensions, model hash and 33 top-left normalized image landmarks. The pinned official Pose Landmarker Lite v1 runs CPU IMAGE mode with `num_poses=2`; no detected person or more than one detected pose returns an empty invalid result. A returned single pose does not prove another person was absent. Service and Unity retain no frame files, participant landmarks or request bodies. This local detector is separate from Silas's offline motion/replay worker and Nathan's media-upload gateway.

Unity validates schema/frame ID/dimensions/model hash, unique finite landmark indices, confidence and bounds. Only shoulders **11/12** and hips **23/24** lift into the room. The SDK's bottom-left viewport receives `(x, 1-y)`. MediaPipe `z` is ignored for depth: it is relative to the hip midpoint, not metric Quest world depth. Each calibrated ray intersects the operator's accepted anterior torso plane. This is a depth approximation with an explicitly supplied surface, not recovered internal joint centers. [Google Pose Landmarker coordinates](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python)

## Generic Source Fit and Gates

The imported atlas frame is meters, anatomical left +X, cranial +Y, anterior −Z. A source-geometry check configures the skeletal/surface reference imports identically to the active organ builder, then checks 37 actual imported bounds/axis/metric assertions. Those reference assets do not become runtime scene dependencies. The joint reference proxies were sphere-fitted from original humerus/femur geometry, not measured from a participant.

The uniform fit uses source shoulder height **1.382441 m**, hip height **0.860876 m**, shoulder width **0.335006 m**, hip joint width **0.168614 m**, and anterior reference Z **−0.115287 m**. Shoulder-to-hip length controls one uniform scale; labeled left/right points and the independently calibrated anterior normal control rotation. Source front hip midpoint is translated onto the observed planar hip midpoint. Organs preserve their shared source proportions. The source umbilicus `(0,1.017768,-0.115287)` supplies the fitted port frame, replacing the virtual mannequin's approximate origin in AR. A planar fit cannot measure torso thickness, internal anatomy or organ accuracy.

Four cyan markers and a render-only **42-part/110,511-triangle** organ overview allow visual inspection before practice. The scored appendectomy keeps its nine authored targets/context meshes and existing exercise rules. The larger overview does not create 42 validated surgeries; the greater omentum is omitted from the overview to avoid covering the other abdominal organs and consuming 77,968 extra triangles. It remains in the scored exercise.

Three stable observations plus explicit **B** are required to accept a fit. B then continues case confirmation. Scoring, coach tracking, anatomy/port visibility and resume commands require the same current accepted fit in AR. No/multiple poses, occlusion, wrong frame/model, malformed points, implausible proportions, mirrored sides, missing surface, lost XR or frame age over **750 ms** invalidate the fit. Accepted anatomy remains fixed; participant movement beyond **35 mm**, **5°** or a **0.05 scale** delta invalidates it and requires visual acceptance again. The source-point residual allowance of **90 mm** is an engineering rejection bound for this approximate correspondence, **not a demonstrated anatomical accuracy**. Retry invalidates acceptance; changing presentation stops the camera and abandons the previous fit/attempt. Virtual effects still use authored exercise contacts rather than arbitrary tissue slicing.

## Run and Verify

1. In `services/registration`: `uv sync --frozen`, then `uv run --frozen scalpal-registration fetch-model`, then `uv run --frozen scalpal-registration serve`.
2. Configure the development player using `scripts/quest/configure_session.py`; this restores coach/Spacetime routes plus localhost8790 and does not start camera capture.
3. Run `scripts/quest/verify_session.py --suite registration` and `--suite unity`. Model download is explicit and separate from serving. The cached model is Git-ignored.
4. Build with `NativeSessionBuild.Build`, which runs the scene/body/input/session verification before producing the APK.

The registration gate passed **33 tests**, including actual in-memory blank-JPEG CPU inference and loopback HTTP. Multi-person output and positive landmark data tests are explicitly synthetic. Unity passed **34 synthetic projection/gate checks**, **37 imported source geometry checks**, and the existing 160 instrument/24 input/75 ten-step playthrough/72 attempt/68 coach checks. Neither suite proves physical body fit, accuracy or frame time.

For the wearer test: launch without acquisition; verify real room visible and mannequin hidden. With an agreed reclining participant in good light, opt in, set the three torso-plane points, inspect all four markers from both eyes and accept. Move the headset without moving the participant: markers must remain on the same external locations. Move the participant or cover a shoulder: organs/ports/effects and scoring must stop, with explicit fit acceptance required after recovery. Check refresh/frame time, source-image orientation, actual service latency and OVR/OpenXR tracking-space compatibility. A manual plane, synthetic editor pose or blank image cannot substitute for this test.

The standalone instrument bench patches retain their authored XR-only interaction gate for workspace testing; they are not fitted patient organs and do not score case progress. The accepted body fit gates the patient anatomy, ports and scored contact path. Arbitrary deformable-organ cutting remains unimplemented.
